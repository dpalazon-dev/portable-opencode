# Contributing

`portable-opencode` is currently in the specification stage. Contributions should preserve the project's core boundaries before adding implementation complexity.

## Before proposing a change

1. Read [`docs/SPECIFICATION.es.md`](docs/SPECIFICATION.es.md).
2. Identify whether the proposal belongs to the core, an optional profile or a future extension.
3. Prefer native OpenCode and OpenRouter capabilities over custom reimplementations.
4. Explain the default, the override mechanism and the validation criterion.

## Changes to the specification

Specification changes should state:

- the problem being solved;
- the affected responsibility or lifecycle phase;
- the adopted decision;
- alternatives considered;
- security, portability and maintenance implications.

## Implementation changes

Implementation has not started. The first implementation milestone will follow an explicit configuration matrix and MVP plan derived from the specification.
